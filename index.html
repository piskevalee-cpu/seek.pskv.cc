The interface, pixel for pixel

These are the real glyphs of the terminal UI · the 25×9 bitmap, the eight-cell streak, the rails and the rounded prompt. Try them below.

01 · THE MARK

25 columns × 9 rows, drawn as ██ or half blocks. Only lit pixels are painted; the terminal shows through.

02 · THINKING
thinking...

Eight cells. A streak travels through them and wraps at the right · the same wave as the logo's sheen.

03 · THE PROMPT
╭[no model selected]╮
│❯│
╰Enter sends · Alt+Enter newline╯

The model name sits in the top border. Type / for commands and skills, @ for project files.

04 · THE TRANSCRIPT
│❯ add a test for the parser
│I'll look at the parser and add a focused test.
│◇ read src/parser.rs

One column of colour per block: blue for you, magenta for the model, grey for tools. The band is yours; the answer is plain text.

05 · THE FOOTER
[no model selected] user/project develop ~0 / 0 · 0%

One line: the permission chip, the model, where you are, and this session's counts. Click the chip to cycle READ → ASK → YOLO.

06 · ONE HOME PER FACT

Nothing is shown twice. The METRICS block lives at the bottom of the sidebar, or in the footer when the sidebar is closed · never both.

thin on purpose

A short prompt, a small toolset, and no hidden machinery.

01

Thin by design

System prompt plus default tool schemas fit in a 1,500-token budget · checked in CI. Five tools, nothing lurking.

02

Local is first-class

Discovers models in ~/seek/models/, starts llama serve, waits for health, reads the real context size and stops the server on exit.

03

Model-agnostic

Switch between a local server, Anthropic and OpenAI-compatible models between turns without losing the conversation.

04

Filesystem is config

No settings database. ~/seek/ holds GGUF models, SKILL.md skills, tool.toml tools, widgets and append-only session JSONL. Every config carries schema = 1, and install is idempotent.

05

The agent can search

web_search takes a query, not a URL, and returns numbered sources from a chain of engines.

06

Nothing hidden

Logs, process ids, context use and speed are always reachable. Every fact has exactly one home on screen.

Bring your own model

The provider boundary lives in one crate; the TUI never talks to an API directly.

LOCAL

llama.cpp

Point SEEK at the unified llama binary. Models are scanned from ~/seek/models/; the server runs as its own process group and shuts down cleanly.

CLOUD

Anthropic

Native messages API with streaming tool use, reasoning variants and prompt caching. Keys live in the environment or state/auth.json.

CLOUD

OpenAI-compatible

Any endpoint that speaks the OpenAI chat protocol · gateways, local servers, hosted models · behind the same catalog and stream parser.

API keys are never written to config.toml or providers.toml, and are redacted wherever they could be logged.

extend without rebuilding

There is no settings database. ~/seek/ is the config: drop a folder in, toggle it with /skills or /tools, and it is live on the next turn. Each contract carries schema = 1, and install.sh is idempotent, so it never overwrites a file of yours.

  • skills/ uses the Agent Skills SKILL.md format; only the name, description and path enter the prompt
  • tools/ declares tool.toml, schema.json and a run script that reads JSON on stdin
  • widgets/ prints up to eight lines from a run script on the home screen
  • state/ keeps append-only sessions, user.toml and auth.json at mode 0600
  • API keys never go in config.toml or providers.toml
~/seek/
├── models/      # gguf files
├── skills/      # SKILL.md
├── tools/       # tool.toml + run
├── widgets/     # widget.toml + run
└── state/
    ├── auth.json      # 0600
    ├── user.toml
    └── sessions/      # append-only jsonl
